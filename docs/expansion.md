# Расширение существующего общего пула

Режим `expand` увеличивает число логических IPv6-прокси в уже проверенной установке
`3proxy-shared-v1`. Старые строки остаются в начале списка с прежними логинами,
паролями, IPv6 и входным портом. Новый логин получает постоянный IPv6. Для `/48`
используются свободные `/64`; для `/64` — свободные адреса внутри неё.

Код доставляется через commit → push → pull. Запуск с локальной машины:

```bash
.venv/bin/python remote_setup_script.py --mode expand --host proxy-host \
  --target-count 5000 --check-concurrency 20
```

По умолчанию используется `/home/3proxy_shared`. Для установки в другом каталоге
указать `--directory`. Сеть, порт и проект читаются из существующего `pool.json`.
Режим первой установки `create` по-прежнему запрещён поверх любого готового пула.
Уменьшение количества режимом `expand` запрещено.

## Применение

1. Проверить завершённую установку, её конфигурацию, установленную службу,
   исходные IPv6 и минимум 512 МиБ доступной памяти.
2. Сохранить старые файлы и подготовить новые в приватном `expansion_state/`.
   Журнал `expansion.json` фиксирует количество, контрольные суммы и стадию.
3. Привязать новые IPv6 и дождаться DAD. До этого рабочие файлы не меняются.
4. Опубликовать четыре файла пула и перезапустить только его службу. Текущие
   соединения прерываются и восстанавливаются клиентами; это плановое переключение.
   DNS, ограничения ресурсов и unit-файл сохраняются.
5. Скачать пул и проверить снаружи **каждую старую и новую идентичность**:
   HTTPS через прокси должен вернуть ровно закреплённый IPv6.
6. Только после полной проверки пометить расширение завершённым и выдавать
   дополнительные записи потребителям.

Повтор с тем же числом использует сохранённые реквизиты. После завершения он
проверяет целостность и службу без перезапуска и повторной генерации. Прерванная
публикация допускает только сохранённые старые или новые хеши каждого файла.
Постороннее изменение останавливает операцию. Следующее увеличение сохраняет
также предыдущее расширение. `--skip-check` оставляет пул непроверенным и возвращает 2.

`deployment.json` остаётся историческим журналом первоначальной установки или
миграции, включая старые доступы для отката. Текущее количество после расширения
нужно читать из `pool.json` и завершённого `expansion.json`. Исторические хеши файлов
пула могут отличаться от текущих; текущие хеши находятся в `expansion.json`.
Обычные команды миграции блокируются при наличии журнала расширения.

Журналы, резервные копии и экспортированные списки содержат секреты: файлы 0600,
каталоги 0700, в публичный Git не включать. Локальный полный список сохраняется
в `downloaded_configs/<host>/extracted_proxy`.

## Ошибки и откат

При ошибке запуска восстанавливаются прежние файлы и служба. IPv6 остаются назначены:
удаление может повредить другим службам или старой установке. После исправления
причины тот же запуск можно повторить. При неудачной внешней проверке новый пул
остаётся в состоянии `verification_failed`; его дополнительные записи не выдавать.

До завершения проверки доступен явный откат:

```bash
.venv/bin/python remote_setup_script.py --mode expand --phase rollback --host proxy-host
```

Откат подтверждённого расширения блокируется: дополнительные логины уже могут
использоваться. Сначала требуется вернуть выбранные рабочие пулы потребителей
через Git, дождаться прекращения использования новых логинов и отдельно выполнить
восстановление нужной сохранённой версии. Не запускать старый миграционный откат
поверх расширенного пула.

## Выдача потребителям и нагрузка

Полный каталог доступных адресов хранить отдельно от выбранных рабочих подмножеств.
Для новых парсеров выбирать нужные записи, сохраняя идентичность `host:port:username`.
Число адресов не задаёт квоту HTTP RPS или WS. Расширение рабочего HTTP-пула может
увеличить число удерживаемых соединений, даже при прежнем RPS; его размер, число
клиентских сессий и соединения к разным доменам нужно учитывать отдельно.

Сервера переключать последовательно. После каждого проверять возврат HTTP,
свежесть каждого прежнего BUY/SELL-направления, память, ошибки и переподключения.
Остановленные приложения сохранять остановленными. Обновление отдельного каталога
и инструкции не требует перезапуска приложений, пока их рабочие списки не меняются.

Проверки: `python -m unittest test_proxy_expansion test_proxy_migration
test_proxy_deployment test_provision_server test_server_preflight test_setup_proxy_logging`.
